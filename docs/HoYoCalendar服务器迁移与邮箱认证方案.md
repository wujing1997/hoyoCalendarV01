# HoYoCalendar 云端后端、同步与 AI Agent 方案

> 状态：最终确认版。用户已于 2026-08-09 批准开始开发。

## 1. 目标与边界

为现有 Electron 桌面日历增加邀请制账号、密码登录、云端数据保存、多设备双向同步、云端 AI Agent 和简洁 Web 管理后台，同时保留未登录、断网时可正常使用的本地优先体验。

首期面向少量受邀测试用户，是允许丢失云端状态的测试版本，不宣称生产级可靠。

本期不做：邮箱验证、邮件发送、忘记密码、自助找回、第三方 OAuth、用户自助导出/注销、单用户 AI 限额、异机数据库备份、多模型路由、公开管理后台、共享日历、WebSocket、微服务、Redis、消息队列和 Kubernetes。

## 2. 现状基线

- 客户端为 Electron 40，使用原生 HTML、CSS、JavaScript。
- `preload.js` 提供安全桥，`src/core/event-store.js` 是日历唯一写入层。
- 日历保存在 `%APPDATA%\HoyoCalendar\events.json`。
- 现有本地 Python/Flask Agent 只生成 action plan，最终由本地 `EventStore` 写入。
- 现有时间戳事件 ID 不适合多设备并发，迁移时统一生成稳定 UUID。

## 3. 最终架构

```text
Electron 桌面端
  ├─ 本地 EventStore / events.json：本地优先、离线可用
  ├─ 认证与设备会话客户端
  ├─ 增量同步、冲突处理与回收站
  └─ AI 候选操作审批界面
             │ HTTPS
             ▼
        Caddy / Nginx
             │
             ▼
      Python 模块化单体 API
       ├─ auth：账号、邀请码、会话
       ├─ sync：事件、游标、冲突、墓碑
       ├─ agent：模型调用、用量、熔断
       └─ admin：管理 API 与审计
             │
             ▼
         PostgreSQL

Web 管理后台仅监听服务器 127.0.0.1，通过 SSH 隧道访问。
```

后端建议使用 FastAPI、SQLAlchemy、Alembic、PostgreSQL。模块同进程部署，不拆微服务；AI 调用设置并发上限和超时，暂不使用队列。

## 4. 账号、邀请与会话

- 注册输入：一次性邀请码、邮箱格式账号、用户自设密码。
- 邮箱仅是唯一账号名，不验证归属；规范化后大小写不敏感唯一。
- 密码使用 Argon2id，仅保存哈希。
- 邀请码只保存哈希，可设置有效期、撤销状态和可用次数；首版一次使用后失效。
- 支持注册、登录、刷新会话、退出、获取当前账号。
- 不提供邮箱验证、忘记密码和自助重置；忘记密码只能后续处理。
- 每个账号最多 5 台设备同时登录。
- 用户可查看设备名和最近活动时间，退出当前设备或撤销其他设备。
- 访问令牌短时有效；刷新令牌轮换，服务端只存哈希；Electron 使用 `safeStorage` 或系统凭据库保存。
- 注册、登录、刷新接口限流；错误文案防止账号枚举。

## 5. 数据模型

### 5.1 核心表

- `users`：UUID、规范化账号、Argon2id 哈希、状态、预留 `email_verified_at`、时间戳。
- `invites`：邀请码哈希、状态、有效期、允许次数、已用次数、创建/使用信息。
- `sessions`：用户、设备 ID/名称、刷新令牌哈希、过期/撤销/最近活动时间。
- `events`：UUID、用户、现有事件完整 JSONB、服务端版本、客户端/服务端时间、删除与回收站时间。
- `sync_changes`：单调游标、用户、事件、操作、版本、时间。
- `ai_usage`：用户、模型、token/费用、耗时、结果码、时间；禁止保存提示词、日历快照和模型回复正文。
- `admin_users` / `admin_sessions`：独立管理员认证与短会话。
- `admin_audit_logs`：管理员、操作类型、目标、结果、时间；不记录密钥和敏感正文。

事件业务数据首期采用“关系列 + JSONB”，保证普通、重复、Deadline 和计时记录字段完整。

## 6. 认证与管理接口

### 6.1 用户接口 `/api/v1`

- `POST /auth/register`
- `POST /auth/login`
- `POST /auth/refresh`
- `POST /auth/logout`
- `GET /me`
- `GET /sessions`
- `DELETE /sessions/{session_id}`

### 6.2 管理后台范围

- 管理员登录/退出。
- 生成、查看、撤销邀请码。
- 查看用户、禁用/启用账号、撤销该用户全部会话。
- 查看脱敏 AI 用量与平台预算状态。
- 配置 AI 总开关与全局预算熔断状态。
- 查看管理员操作审计。

管理后台绑定 `127.0.0.1`，只能通过 SSH 隧道访问；使用独立管理员账号、Argon2id 密码、短会话、限流和审计，不与普通用户角色混用。

## 7. 同步协议

- `POST /api/v1/sync/push`：批量提交 `{operationId, eventId, baseVersion, op, data}`。
- `GET /api/v1/sync/pull?cursor=&limit=`：返回增量变化、下一游标和是否还有数据。
- 写入以 `operationId` 保证重试幂等，以 `baseVersion` 做乐观并发控制。
- 所有查询、变更和游标必须绑定认证用户，用户 A 不得访问用户 B 数据。

### 7.1 自动同步

- 本地修改立即落盘并进入待同步队列，短暂防抖后推送。
- 应用启动、恢复联网和定时心跳时拉取。
- 支持“立即同步”。
- UI 必须显示：已同步、待同步、离线、冲突、同步失败。
- 网络失败指数退避，不阻塞本地编辑。

### 7.2 冲突

- 不使用客户端时钟决定最后写入者，不静默覆盖。
- 基础版本不一致时服务端返回冲突和云端版本。
- 客户端同时保留本机/云端两版，用户选择后生成新的明确写入。

### 7.3 删除

- 删除进入 30 天回收站，可恢复。
- 30 天后清除事件正文，最小删除墓碑保留 180 天。
- 超过同步窗口的旧设备上线时强制全量校准，禁止复活已删除事件。

## 8. 旧数据与首次登录

1. 升级前创建只读备份，不覆盖原 `events.json`。
2. 为旧事件生成稳定 UUID，保留旧 ID 映射，迁移可重复执行且不产生重复。
3. 增加版本、操作 ID、同步状态和删除元数据；业务 UI 与 AI 快照过滤内部字段。
4. 云端为空则自动上传本地；本地为空则自动下载云端。
5. 两边都有数据时按 UUID 合并；同一事件冲突进入双版本选择，禁止整库覆盖。
6. 完成后校验总数、事件类型、关键字段和抽样内容，并展示迁移摘要。

## 9. 云端 AI Agent

- 平台统一提供并承担模型账号费用。
- 服务端通过环境变量配置单一 OpenAI-compatible `BASE_URL`、`API_KEY` 和默认模型；客户端不可查看密钥。
- 需要真实 API Key 时暂停在配置步骤，由用户本人直接在服务器安全配置中填写；不得通过 issue 评论、代码、数据库或日志传递。
- 桌面端按请求上传必要日期范围内的最新本地快照；后端校验用户身份和请求大小。
- Agent 仅返回结构化 action plan，不读写 PostgreSQL 或本地文件。
- 桌面端展示候选新增/修改/删除，支持逐项同意/拒绝和一键同意；仅批准项由本地 `EventStore` 执行后同步。
- 断网时 AI 显示不可用，不排队；普通日历继续工作。
- 服务端请求结束即丢弃提示词、快照和模型回复，只留脱敏用量元数据。
- 测试期不设单用户额度；必须保留平台全局月预算硬熔断、管理员总开关、并发上限、请求超时和用量审计。

## 10. 部署

- 目标为用户 SSH 配置中的腾讯云服务器。
- Docker Compose 管理 API、PostgreSQL 和反向代理；PostgreSQL 不开放公网。
- 开发与内部验收通过 SSH 隧道；邀请外部测试前购买域名并启用可信 HTTPS。
- 提供 `/healthz`、结构化脱敏日志、Alembic 迁移和上一镜像回退步骤。
- 所有数据库口令、令牌 pepper、管理员凭据和模型密钥由环境变量或服务器密钥文件提供，禁止入库入仓。
- 按用户决定，测试期不做异机数据库备份。服务器故障可能丢失账号、会话、游标、冲突和云端状态；客户端副本不能完整重建。

## 11. 开发分工

### 后端开发与云端部署智能体

- 实现模块化单体、数据模型、迁移、认证/邀请/设备会话、同步协议、冲突/墓碑、Agent 网关、用量熔断、管理 API、审计和 Compose 部署。
- 交付 OpenAPI 契约、迁移说明、环境变量模板（无密钥）、自动化测试和部署/回退证据。
- 不修改桌面 UI，不代填 API Key，不把测试期限制擅自升级为生产功能。

### 前端智能体

- 实现注册登录、设备管理、同步状态、立即同步、冲突双版本选择、回收站、首次迁移摘要、AI 候选操作审批和 Web 管理后台页面。
- 沿用现有 UI 风格和安全桥；不得绕过 `EventStore` 直接写数据。
- 依据 OpenAPI 契约集成，不自行发明后端字段。

### 独立测试智能体

- 当前小队尚无测试智能体，独立复验在开发完成前必须补齐。
- 覆盖认证、邀请码、设备限制、越权、令牌撤销、迁移、断网、幂等、冲突、删除/恢复、旧设备全量校准、AI 审批、密钥/日志泄露、管理权限和现有功能回归。

## 12. 验收标准

- 未登录/断网仍可使用本地日历；恢复联网后操作只同步一次。
- 邀请码一次性有效；密码不明文落盘；第 6 台设备被明确拒绝；撤销会话立即失效。
- 普通、重复、Deadline 和计时记录迁移后字段与行为一致，原文件有可用备份。
- 首次合并不整库覆盖；双设备冲突保留两版并由用户处理。
- 删除可在 30 天内恢复，超期离线设备不会复活删除项。
- 用户间数据严格隔离；越权请求失败且不泄露存在性。
- AI 不直接写数据；每项候选操作未经批准不得执行，部分批准只执行选中项。
- AI 正文不持久化，模型密钥不出现在仓库、数据库、日志、客户端包或 issue 评论。
- 全局预算熔断只暂停 AI，认证、日历和同步继续可用。
- 管理后台不对公网监听，未授权用户无法访问，关键操作有审计记录。
- 自动化单元/集成测试、桌面构建、关键流程冒烟和现有回归均通过，并提供实际命令与结果。
- 因用户选择不做异机备份，不把备份恢复列为本期通过条件；必须在交付说明中显著披露数据丢失风险。

## 13. 实施顺序

1. 后端确定数据库与 OpenAPI 契约，并实现云端模块。
2. 前端依据冻结契约实现 Electron 和管理后台交互。
3. 后端部署到腾讯云测试环境；需要模型密钥时通知用户现场填写。
4. 独立测试智能体执行测试；缺陷分别退回责任智能体修复后复验。
5. 研发总管依据实现、测试、部署证据验收，通过后交付用户手工测试。
