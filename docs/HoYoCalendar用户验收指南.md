# HoYoCalendar V3.0 云端版用户验收指南

> **⚠️ 历史受邀测试记录：本文档描述的是 V3.0.0 受邀测试版本，已由 V3.0.1 取代。**
> 文中所有安装包路径、SHA256 与版本号（3.0.0）均属**历史记录**，不再代表当前版本；
> 正式版本请以 GitHub Releases 为准，下载 `HoYoCalendarV3.0.1-setup.exe`。

> 本文档基于 2026-08-10 对当前实际安装包、服务器与隧道的逐项实测编写，验收对象为
> 「本地日历 + 云端账号 / 双向同步 / AI 审批 / 管理后台」的受邀测试版本。

## 0. 当前交付状态（务必先读）

- **尚无正式 Release**：当前安装包为本地构建产物，尚未发布 GitHub Release，
  PR #1（云端后端）与 PR #2（前端）也尚未合并。
- 当前有效代码分支：`agent/agent/ef3ad0c0`（PR #2，含云端前端与管理后台部署文档）。

- 服务器所有服务仅监听 `127.0.0.1`，公网不可直连，**必须通过 SSH 隧道访问**。

## 2. 方式一：用安装包启动

1. 双击 `D:\vscodeprojects\hoyoCalendar\dist\HoYoCalendarV3.0-setup.exe` 安装。
   安装为一键式（无自定义目录选项），完成后开始菜单出现快捷方式 **HoYoCalendar**。
2. 点击快捷方式启动。运行日志首行应形如：

   ```text
   HoYoCalendar starting version=3.0.0 packaged=true
   ```

   版本也可在应用内查看：设置（齿轮图标）→「关于」区域显示 `V3.0.0`。

3. 应用为单实例：重复启动不会开第二个窗口，而是聚焦已打开窗口。
   如需强制多开（仅调试用）：先设置环境变量 `HOYO_ALLOW_MULTIPLE_INSTANCES=1` 再启动。

也可不安装，直接运行解包目录：

```text
D:\vscodeprojects\hoyoCalendar\dist\win-unpacked\HoYoCalendarV3.0.exe
```

## 3. 方式二：从源码启动

前置要求：Node.js 18+。**不需要 Python**（旧版本地 Flask 后端已移除，云端服务在服务器上）。

```bash
# 取含云端功能的代码（PR #2 分支）
git clone --branch agent/agent/ef3ad0c0 https://github.com/wujing1997/hoyoCalendarV1.git
cd hoyoCalendarV1
npm install
npm start
```

启动日志应只有一行 `HoYoCalendar starting version=3.0.0 packaged=false`，
**不应**再出现旧版的 `Starting backend python port=5001` 或 `Backend readiness false`
（那是旧版缺陷，本轮已修复）。

## 4. 建立 SSH 隧道

打开一个 PowerShell 窗口并保持运行，执行（任选其一，效果相同）：

```powershell
# 使用本机 SSH 配置别名
ssh -L 8000:127.0.0.1:8000 -L 8080:127.0.0.1:8080 腾讯云服务器
```

```powershell
# 或直接用 IP 与用户
ssh -L 8000:127.0.0.1:8000 -L 8080:127.0.0.1:8080 ubuntu@124.223.41.137
```

验证隧道（另开一个窗口执行，应看到与下文一致的输出）。

方法一：`curl.exe`（Windows 10 1803+ 自带，注意必须写 `curl.exe`，Windows
PowerShell 5.1 中裸 `curl` 是 `Invoke-WebRequest` 的别名，`-s/-m/-o/-w` 参数无法执行）：

```powershell
curl.exe -s -m 5 http://127.0.0.1:8000/healthz
# 期望：{"status":"ok","version":"0.1.0","database":"up",...}

curl.exe -s -o NUL -w "%{http_code}" -m 5 http://127.0.0.1:8080/
# 期望：200（管理后台页面可访问）
```

方法二：原生 PowerShell（PowerShell 5.1 / 7 均可直接执行）：

```powershell
(Invoke-RestMethod -Uri http://127.0.0.1:8000/healthz -TimeoutSec 5).status
# 期望：ok

(Invoke-WebRequest -Uri http://127.0.0.1:8080/ -TimeoutSec 5 -UseBasicParsing).StatusCode
# 期望：200（管理后台页面可访问）
```

**注意**：隧道窗口关闭即断网，应用内会显示「离线/无法连接云端服务」；验收期间保持
该窗口开启。

## 5. 配置服务地址（云端服务器地址）

1. 启动应用后，点击顶栏右上角的**账号图标**（或顶栏左侧的「未登录」状态胶囊），
   打开「账号与云端同步」面板。
2. 找到「服务器」区域，在「云端服务器地址」填入：

   ```text
   http://127.0.0.1:8000
   ```

3. 点击「保存服务器地址」。

地址保存在本机配置文件：

```text
%APPDATA%\HoyoCalendar\config.json
```

对应字段为 `cloud.serverUrl`。测试期填写 SSH 隧道地址；正式部署 HTTPS 后改填
服务器域名。默认值即为 `http://127.0.0.1:8000`，不修改也能用。

## 6. 首次注册 / 登录

### 注册（需要邀请码）

1. 打开「账号与云端同步」面板 → 切到「**邀请码注册**」标签。
2. 填写：**邀请码**（管理员在管理后台生成）、**邮箱**（如 `name@example.com`）、
   **密码**（至少 8 位）。
3. 点击「注册并登录」。成功后提示「注册成功」，面板变为已登录状态。
4. 首次登录会自动执行**数据迁移**：本机旧日程（`%APPDATA%\HoyoCalendar\events.json`）
   会备份为 `events.backup-<时间戳>.json`，再与云端做首次合并，面板显示
   「上传 / 下载 / 合并 / 冲突」统计。

### 登录（已有账号）

面板 → 「登录」标签 → 邮箱 + 密码 → 「登录」。

登录令牌的刷新令牌加密保存在本机 `%APPDATA%\HoyoCalendar\cloud-credentials.bin`，
下次启动会自动恢复会话（无需重新登录）。

### 设备管理

「账号与云端同步」面板显示已登录账号与设备列表：同一账号最多 **5 台设备**，
第 6 台会注册/登录失败；可撤销非当前设备（「撤销」按钮），撤销后该设备令牌立即失效。

## 7. 同步与冲突

- 顶栏左侧有同步状态胶囊：**未登录 / 已同步 / 待同步 / 离线 / 冲突 / 同步失败**。
- 新增、修改、删除、完成等本地操作会在 3 秒内自动排队推送；登录后每分钟自动拉取云端
  变更；也可在「账号与云端同步」→「同步」区域点「**立即同步**」。
- 断网期间修改会进入本地队列（`sync-queue.json`），恢复网络后自动补推。
- **冲突**：同一日程本机与云端都改过（版本不一致）时，状态变为「冲突」，面板显示
  「N 项冲突待处理」，点击进入冲突列表，可对比「本机版本」与「云端版本」并选择：
  - 「**保留本机**」：以本机为准并覆盖云端；
  - 「**采用云端**」：以云端为准覆盖本机。
- **回收站**：删除的日程进入回收站保留 30 天（本地 + 云端），可随时恢复；云端删除
  的日程同样会同步到本机回收站。

## 8. AI 日程助手（含审批）

1. 点击顶栏的**日程助手**按钮（魔法棒图标）。
2. 输入自然语言指令，例如：

   ```text
   明天9点项目会议45分钟
   把下周一的健身移到周二
   删除本周三 15:00 的会议
   8月10号前写完论文
   ```

3. AI 返回**候选操作列表**（不会直接改日程），每项标注「新增 / 修改 / 删除」及内容
   摘要，卡片下方显示用量与剩余预算。
4. 审批操作：
   - 「**一键同意**」：执行全部候选；
   - 「**仅执行选中项**」：先勾选部分项再执行；
   - 「**全部拒绝**」：忽略全部，不写入任何日程。
5. 未登录时助手提示「登录后可使用云端日程助手」；未配置 AI 的账号会提示云端不可用，
   本地日历功能不受影响。

> 说明：设置面板里豆包 / Ollama / OpenAI 的 API 配置仅作**兼容入口保留**，只保存到
> `config.json` 不再生效；实际对话一律由云端 Agent 提供。不要在设置里误填密钥后
> 期望生效。

## 9. 管理后台（Web）

1. 保持第 4 步的隧道开启，浏览器访问：

   ```text
   http://127.0.0.1:8080
   ```

2. 使用服务器 `.env` 中的管理员用户名与密码登录（用户名与原始密码由管理员提供，
   本文档不写入）。
3. 后台包含 5 个标签：

   | 标签 | 用途 |
   | --- | --- |
   | 邀请码 | 生成新邀请码（次数/有效期）、复制、撤销；邀请码用于客户端注册 |
   | 用户 | 查看用户列表，可禁用账号 |
   | AI 用量 | 各用户 AI 用量脱敏汇总 |
   | 设置 | AI 全局开关与月度预算 |
   | 审计 | 管理操作审计日志 |

4. 登录令牌仅保存在浏览器 `sessionStorage`，关闭浏览器即失效。**「退出登录」只清除
   浏览器中保存的令牌并调用一次服务端 logout（当前为 no-op，返回 204），不会撤销
   已签发的服务端会话**：已签发的管理 JWT 是无状态令牌，最长仍可在 1 小时内有效
   （服务端默认 `ADMIN_TOKEN_MINUTES=60`）。如怀疑令牌泄露，需联系部署方更换
   `ADMIN_TOKEN_SECRET` 并重启管理服务，仅退出登录或关闭浏览器无法使其立即失效。

## 11. 退出与常见故障

### 正常退出

- 点窗口右上角关闭按钮，应用即完全退出（无托盘驻留）；`before-quit` 会保存窗口状态。
- 全部窗口关闭时进程自动退出（Windows）。

### 常见故障

| 现象 | 原因与处理 |
| --- | --- |
| 提示「无法连接云端服务，请检查服务器地址或网络」 | 隧道未建立或已断开：确认第 4 步窗口在运行；`curl http://127.0.0.1:8000/healthz` 验证 |
| 登录/注册提示「请重新登录」或 401 | 令牌过期或设备被撤销：重新登录即可 |
| 状态一直「待同步」 | 队列有积压：保持在线，点「立即同步」；长期失败看日志 |
| 提示「端口被占用」/隧道连不上 | 本地 8000/8080 被其它程序占用：改用 `ssh -L 18000:127.0.0.1:8000 -L 18080:127.0.0.1:8080 ...`，并把应用内服务器地址同步改为 `http://127.0.0.1:18000`、后台访问 `http://127.0.0.1:18080` |
| 安装时被杀毒软件拦截 | 本地构建包无签名，属预期：添加信任后重试 |
| 重复打开没反应 | 单实例锁生效：聚焦已有窗口即可 |
| 第 6 台设备注册/登录失败 | 设备数已达上限：到已登录设备撤销一台，或联系管理员 |

### 日志与数据位置

```text
%APPDATA%\HoyoCalendar\
  config.json              本地配置（含 cloud.serverUrl）
  events.json              本地日程数据
  events.backup-<时间戳>.json  迁移前的旧数据备份
  sync-state.json          同步状态（服务器地址、游标、账号、冲突）
  sync-queue.json          待推送变更队列
  cloud-credentials.bin    加密保存的刷新令牌
  logs\main-YYYY-MM-DD.log 运行日志（应用内：设置 → 关于 → 「打开日志目录」）
```
